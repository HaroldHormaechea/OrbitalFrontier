# UC-42 — Loot & salvage from destroyed hostiles — FINAL APPROVED PROPOSAL

(Consolidated: original proposal with all challenger-required revisions folded in. Use-case: `/workspace/OrbitalFrontier/use-cases/42-loot-salvage-economy.md`. Analyst↔challenger APPROVED in 2 rounds.)

## Analysis

**Current state (verified by reading source):**
- `combat/Combat.step` (Combat.kt) is the single pure tick the device (`PlayScreen.stepCombatOnce`, ~L1527) and the headless mirror (`sim/Simulation.kt`, combat block ~L473–605) both call. On a kill it emits `CombatEvent.HostileDestroyed(id)` and **culls** the hostile; when the last hostile dies the step returns `CombatState.NONE` with `EncounterCleared` (Combat.kt L209–235). **Today destroyed hostiles drop nothing** (combat.md "Loot/salvage… destroyed hostiles drop nothing yet").
- UC-41 wiring is the template: both callers capture `preStepZoneId` BEFORE the step, then `val killsThisTick = result.events.count { it is HostileDestroyed }` and fold into `BountyTracking.applyKills(...)` (PlayScreen L1543–1582; Simulation L546–571). Bounty pays a credit reward on the completing kill.
- `CombatState` (hostiles/projectiles/rng) is **transient** — never persisted, reconstructed as `NONE` on load (ADR 0012); it is NOT in `StateSnapshotDto` (Playthrough.kt `from(state)` L637 omits it). `WorldState`/`SimulationState` carry it but the codec drops it.
- `economy/Cargo` already gives capacity-bounded `add(resource, units): CargoTransfer(cargo, acceptedUnits)` — partial-fill is a first-class result (Cargo.kt L57–66). `ResourceType` declaration order is the canonical deterministic order (used by `Respawn.jettison`).
- Seeded RNG primitive is `common/DeterministicRng` (`fnv1a` → LCG); combat uses the functional `CombatRng.seeded("encounter:$zoneId:$spawnTick")`.
- Notifications: `notify/GameNotifications` builders + `NotificationQueue` (PlayScreen `notifications.enqueue(...)`). `forCombatEvent` maps every per-shot event to `null` (flood defense). Simulation is headless → **no** notifications there.
- `Hostile` exposes `archetypeId` and `kinematics.position`; `applyCreditChange` is the PlayScreen credit chokepoint; `GameNotifications.actionRejected(reason)` exists; both Simulation return paths are real (L584 destroyed, L608 normal). DTO opt-in confirmed: `Playthrough` (L88) and `StateSnapshotDto` (L472) use class-level `@OptIn(ExperimentalSerializationApi::class)`; `combatConfig` (L101) is NOT `@EncodeDefault(NEVER)` and `CombatParamsDto` (L351) has only `@Serializable` with all-required fields.
- Dependency direction: `combat` already depends on `economy` (Respawn imports `Cargo`/`ResourceType`), so loot code belongs in `combat`, depending on `economy`.

**Key structural finding:** salvage must **outlive the encounter** — the final kill clears combat to `NONE`, so a drop stored inside `CombatState` would vanish exactly when the player needs to fly over it. Therefore salvage drops live in `WorldState`/`SimulationState` as a **transient** list (mirroring how combat is transient: in the snapshot type, excluded from the DTO), collected by proximity each tick **outside** the combat branch.

## Proposed Solution

Loot is seeded off already-deterministic ids, generated by the **caller** from the existing `HostileDestroyed` events — so **`Combat.kt`, `CombatEvent.kt` and all combat fixtures stay byte-identical** (no new RNG draws in the combat tick). Combat model untouched.

### New pure types (production), engine-free, package `combat`:
1. **`core/src/main/kotlin/com/orbitalfrontier/combat/SalvageDrop.kt`** — `@JvmInline value class SalvageId(Long): Comparable`; `data class SalvageDrop(id: SalvageId, position: Vec2, credits: Long, resources: Map<ResourceType,Int>)`. A transient world-space wreck.
2. **`combat/LootTable.kt`** — authored per-`HostileArchetypeId` loot catalog (mirrors `HostileArchetypes`: authored object, NOT persisted/pinned) + a pure roll: `LootTable.roll(archetypeId, seedKey: String): LootResult(credits, resources)` using `DeterministicRng.fnv1a(seedKey)` then LCG draws. Loot contents/odds are `[TUNE]`. RAIDER/SCAVENGER each get a small table (credits range + a couple of resources with drop odds).
3. **`combat/Salvage.kt`** — pure orchestrator:
   - `spawn(destroyed: List<(SalvageId, position, archetypeId)>, zoneId, …): List<SalvageDrop>` — one drop per kill via `LootTable.roll("salvage:$zoneId:${hostileId.value}")`. Stable seed ⇒ replay-stable (AC#4).
   - `collect(drops, playerPosition, cargo, credits, pickupRadius): CollectResult(drops, cargo, credits, collectedCredits, acceptedUnits, overflow: Boolean)`. For each drop within `pickupRadius` (processed in `SalvageId` order): add credits (uncapped) + add resources via `Cargo.add` in `ResourceType` order (partial). Fully fits ⇒ drop removed; leftover ⇒ drop's credits set to 0, resources reduced to remainder, kept in world, `overflow=true`. A drop with nothing collectable this tick is left **unchanged** (no event, same-instance) so a full-hold player sitting on a wreck doesn't spam. Deterministic overflow (AC#3). Same-instance no-op when no drop is in range (mirrors `BountyTracking`/`Combat.step`), so non-salvage ticks stay byte-identical.

### State changes (transient — NO schema bump, v19 unchanged):
4. **`world/WorldState.kt`** — add `val salvage: List<SalvageDrop> = emptyList()` and `val nextSalvageId: Long = 0L`, both transient (documented like `combat`: in the snapshot type, **omitted** from `StateSnapshotDto`). No persistence, no migration, no `SaveVersion` bump.
5. **`sim/SimulationState.kt`** (test source, deterministic mirror) — add the identical two fields, defaulted, so pre-UC42 fixtures construct & step byte-identically and replay equality covers salvage.
6. **`combat/CombatParams.kt`** — add `salvagePickupRadius: Float = 64f` (`[TUNE]`) + `init` positivity check (matches `hitRadius`/`spawnDistance`). **`CombatParamsDto` (Playthrough.kt L350–383):** add class-level `@OptIn(ExperimentalSerializationApi::class)` (exactly as `StateSnapshotDto` L472 / `Playthrough` L88; `ExperimentalSerializationApi` already imported L44) **and** the new field as `@EncodeDefault(EncodeDefault.Mode.NEVER) val salvagePickupRadius: Float = <derived>` (template: `Playthrough.reputationConfig`/`bountyConfig` L104/L108, `StateSnapshotDto.reputation`/`stations` L570/L579); thread through `toParams()`/`from()`; keep `DEFAULT = from(CombatParams())` as single source of truth. **Consequence:** because the field is `@EncodeDefault(NEVER)` and equals the domain default, all 14 existing `combatConfig` blocks serialize byte-identically (key omitted) → **no fixture regeneration; round-trip/stability tests stay green.** Loot *table* values are NOT pinned — archetype-stat precedent: a loot retune regenerates the uc42 fixture, exactly as an archetype-HP retune already would.

### Wiring — mirrored byte-for-byte in BOTH callers (HARD per project rule #1):
**Tick rule (pins Issue-2 lockstep):** Collection runs **once per tick, unconditionally, at a single fixed point: immediately after movement is resolved and BEFORE the combat step/branch**, using the post-movement player position. **Spawn** stays where kills are detected (in the combat branch). This makes collect structurally immune to the `result.destroyed` early-return (collect already happened before it), and both callers collect at the same position. Salvage spawned on tick N is collectable from tick N+1 — a deterministic, harmless one-tick latency. Docked ticks still run collect (no-op, no salvage near stations) — no docked/flight special case.

7. **`screen/PlayScreen.kt`** (production):
   - **Spawn** in `stepCombatOnce` (~L1565, beside the existing `killsThisTick` bounty fold): for each `HostileDestroyed` id, look it up in the **pre-step** `combat.hostiles` (captured beside `preStepZoneId`) → `kinematics.position` + `archetypeId`; call `Salvage.spawn`; append to `worldSalvage`, advancing `nextSalvageId`.
   - **Collect** in a new per-frame `collectSalvage()` run in the gated flight advance **after the movement/physics update and before `runCombat`**, using the live ship position. Route collected credits through the existing `applyCreditChange` chokepoint (so the `+N CR` toast fires); fold cargo onto the active ship. On `overflow` enqueue `GameNotifications.actionRejected("CARGO FULL")` (reuse existing kind — no new `NotificationKind`, no purity-guard churn). On a value-moving tick (`collectedCredits > 0 || acceptedUnits > 0`) call `autosave.onEvent("salvage-collected")` (same pattern as `autosave.onEvent("hostile-destroyed")`, L1591) — makes AC#2 durability event-driven, not periodic-timing-dependent.
8. **`sim/Simulation.kt`** (the mirror): identical **spawn** in the `killsThisTick` block (~L554), threaded into **both** return paths (destroyed early return L584 AND normal return L608); **collect** at the single fixed point after movement (post-movement `nextShip.position`, computed at `updatedActive` ~L471) and before the combat branch, threaded into the returned `SimulationState`. **No notifications, no autosave** here (headless).

### Bounty vs. salvage (AC pitfall — explicit decision):
**They stack and do NOT double-count**, because they are *different credits*: `BountyTracking` pays the authored **contract reward**; salvage is the **physical wreckage** (scrap credits + resources) from a separate `LootTable` roll. The economy note lists them as distinct income streams. The two code paths are fully independent (BountyTracking unchanged; salvage added separately) so no single kill's reward is ever applied twice. The *amount* split is `[TUNE]`. Fallback if the user objects: make salvage **resources-only** (no credits) so credits originate from exactly one place — structurally trivial to switch.

## Risks & Considerations
- **AC#3 overflow notification is PlayScreen-only**; the replay test (headless) asserts the cargo/credits/salvage outcome, not the toast. Matches how all UC35 notifications are device-only.
- **Persistence (deliberately none).** Salvage drops are transient wreckage; like `CombatState` they reconstruct empty on reload. A drop *collected* before close is durable — credits→`game_state.credits`, resources→cargo rows — committed via the explicit `autosave.onEvent("salvage-collected")` on the collecting tick (not periodic-timing-dependent). A drop *spawned-but-uncollected* at close is lost — consistent with combat being cleared on reload (ADR 0012). This avoids a v19→v20 migration + baseline-db regen. If uncollected wrecks must survive reload, that is a schema bump and a scope escalation.
- **Loot-table values are `[TUNE]` and un-pinned** (archetype-stat precedent) → a future loot retune regenerates the uc42 fixture, same maintenance contract as today's archetype HP. The pickup *radius* IS pinned (CombatParamsDto) so geometry changes can't silently invalidate the replay.
- **Bounty+salvage stacking** is a balance/design decision — surfaced for the user; structurally safe either way (resources-only fallback available).
- **Spawn position is the pre-step (start-of-tick) hostile position**, ~one tick stale vs. exact death point. Immaterial at pickup-radius scale and identical in both callers (deterministic). Enriching `HostileDestroyed` for exact position was rejected — strictly larger blast radius (Combat.kt + CombatEvent.kt + 4 test call sites) for no functional gain.
- **Lockstep risk (project rule #1):** spawn+collect MUST be identical in PlayScreen and Simulation or live/replay diverge. Mitigated by the shared pure `Salvage`/`LootTable` functions (both callers invoke the same pure code; only thin wiring differs) and the fixed before-combat-branch collect point.

## Challenger final verdict
APPROVED (round 2). Blocking issues caught and fixed: (1) Major — `salvagePickupRadius` on `CombatParamsDto` would have broken all 14 committed fixtures; fixed with `@EncodeDefault(NEVER)` + `@OptIn` + derived default → byte-identical, no regen. (2) Major — live/replay divergence: sim's `result.destroyed` early-return skipped the collect step; collection now runs unconditionally after movement / before the combat branch in both PlayScreen and Simulation. Plus two minors: autosave-on-collect durability; replay assertion derived from actual `LootTable.roll` (no magic numbers).
